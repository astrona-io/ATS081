# Summary

A developer portal brings discovery, documentation and supported tasks into a consistent interface. It can use a catalog to connect ownership and external identities, while platform APIs and controllers perform the actual work. Adoption depends on usefulness, freshness and clear outcomes rather than mandated visits. APIs and other interfaces can serve the same capabilities for different users. The portal should simplify access without concealing responsibility or exposing privileged integration credentials.
