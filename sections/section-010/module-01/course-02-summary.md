# Summary

Self-service lets users request and use supported capabilities without unnecessary coordination. Clear inputs, authorization, automated handling and observable outcomes make that promise practical. Guardrails constrain unsafe or unsupported choices while preserving actionable feedback. A button that silently opens a manual ticket is a different service model. Exceptions and support remain important, but their scope and ownership should be explicit rather than hidden behind an apparently automatic interface.
